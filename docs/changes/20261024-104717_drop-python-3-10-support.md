# Summary

- `requires-python` in `pyproject.toml` changed from `>= 3.10` to `>= 3.11`. The CI matrix already tested only 3.11 through 3.14.
- The project was regenerated from copier-UvScaffolding v0.5.14 (previously v0.5.11).
- The release produces a **minor** version increment because dropping a supported Python version changes who can install the package.

# What Changed

## Package metadata (`pyproject.toml`)
- Minimum Python version raised to 3.11.
- `uv_build` build backend requirement raised to `>=0.13.5,<0.14.0`.
- pytest now also writes an HTML coverage report (`--cov-report html`) and uses `-vvv`.
- Formatting only: author list, `python_files`, and ruff `ignore` comments were reformatted.

## CI/CD workflow (`.github/workflows/CICD.yml`, `CICD_impl.yml`)
- Added a `concurrency` group. Superseded pull request runs are cancelled. Each push gets its own group, so a pending push run that carries a release is never cancelled.
- Renamed the input `python_package_version` to `build_python_version`, the job `package_coverage` to `postprocess_coverage`, and the output `package_name` to `wheel_filename` (the value was always the wheel filename).
- Added `timeout-minutes` to every job.
- Removed `uv sync --frozen` steps that were not needed.
- The build fails unless `dist` contains exactly one wheel.
- Expression interpolation inside `run:` scripts was replaced with environment variables, which prevents script injection and quoting errors.

## Release action (`.github/actions/release_impl/`)
- Values that were read from job-level `env` are now explicit inputs: `wheel_filename`, `package_version`, `coverage_total`.
- New `retry.sh` retries network operations (tag push, release creation) up to 3 times.
- Rerunning a release uploads to the existing GitHub release instead of failing.
- The minisign private key is written to a `mktemp` file under `RUNNER_TEMP` and removed by an `EXIT` trap, so it does not persist on self-hosted runners. All artifacts are signed in one Python process.
- The coverage badge is updated only when a coverage total is available.
- Secrets reach `run:` scripts only through environment variables.

## Documentation
- `README.md`: corrected the signature extension (`.minisig`, not `.minisign`), removed a stray trailing backtick from the verification command, and made the command print a confirmation.
- `DEVELOPMENT.md`: updated the signing command and added a "Semantic Versioning" section that explains `+minor`, `+major`, and `+feature`.
- `src/AutoGitSemVer.yaml` and `.github/release_sources.yaml` now carry comments saying the two lists must stay in sync.

# Why

- Python 3.10 reached end of life in October 2026. It was already missing from the CI test matrix, so the declared support was never tested.
- The template update brings this repository in line with the current UvScaffolding release. It fixes reliability issues: transient network failures, non-rerunnable releases, and cancelled pending push runs that skipped a release. It also fixes security issues: secrets interpolated into scripts, and a signing key left in `/tmp`.

# Impact

- Users on Python 3.10 can no longer install new releases. Earlier releases remain available.
- Repositories or tooling that reference the renamed workflow inputs or outputs (`python_package_version`, `package_name`, `package_coverage`) must be updated.
